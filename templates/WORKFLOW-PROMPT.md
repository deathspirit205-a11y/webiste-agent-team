# Reusable Website Project Workflow

Use with `web-project-orchestrator` after completing `docs/PROJECT-BRIEF.md`.

1. Safety: inspect instructions, repo, stack, branch, Git status and diffs. Preserve uncommitted work. Do not reset, stash, clean, checkout, commit, push, merge or deploy.
2. Discovery: delegate read-only business/competitor research, SEO research, IA/UX audit and technical audit. Require sources, evidence, confidence and gaps.
3. Plan: combine diagnosis, audience/conversion strategy, keyword map, sitemap, page briefs, design direction, technical plan, migration plan, risks, file ownership and acceptance tests.
4. Approval: stop for user approval of scope, architecture, claims, design and file ownership.
5. Implement: one owner per file or isolated worktree. Research may run in parallel; shared layout/config/navigation/global CSS have one owner at a time. Make small changes, preserve functionality, avoid thin pages and fabricated facts.
6. QA: independent QA, accessibility, security and technical SEO checks. Fix blockers and rerun tests.
7. Handover: report changes, routes, tests, known limits, client decisions, rollback and verdict.

Never commit, push, merge or deploy without explicit user approval.
